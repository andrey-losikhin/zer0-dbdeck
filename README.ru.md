# zer0-dbdeck

Нативный DB-клиент для Linux с приоритетом CachyOS, Wayland и аккуратного современного интерфейса.

В приложении уже можно создавать, проверять, редактировать и удалять профили PostgreSQL и MySQL/MariaDB, помечать их как `prod`, `stage` или `local`, задавать цвет, держать несколько подключений и таблиц открытыми во вкладках, просматривать схемы и таблицы, сортировать и фильтровать данные. Табличные данные и результаты SQL отображаются в локально встроенной Tabulator 6.6.1 внутри WebKitGTK 6.0; сетевые загрузки библиотеке не нужны. Сетка поддерживает диапазоны, копирование/вставку, изменение ширины столбцов и редактирование ячеек с сохранением через Rust. Просмотр таблиц подгружает следующие страницы по прокрутке. SQL-вкладки включают подсветку, подсказки объектов и полей, выполнение запросов и экспорт результата. Пароли хранятся в локальном зашифрованном vault. Для таблиц доступен CSV-экспорт показанных строк или всей таблицы.

## Сборка

Системные зависимости Arch/CachyOS: `rust`, `cargo`, `gtk4`, `webkitgtk-6.0`, `libadwaita`, `gtksourceview5` и `pkgconf`.

```sh
sudo pacman -S --needed rust gtk4 webkitgtk-6.0 libadwaita gtksourceview5 pkgconf
cargo run --locked
```

DBDeck хранит профили, пароли и SQL-рабочее пространство в `$XDG_DATA_HOME/zer0/zer0-dbdeck/connections.dbdeck`. Файл зашифрован AES-256-GCM; ключ получается из мастер-пароля через PBKDF2-HMAC-SHA256 с уникальной солью и 600 000 итераций. В настройках можно включить автоматическую разблокировку через системную связку ключей или gopass. Пароли подключений также могут читаться из отдельных записей gopass. При переносе файла на другой компьютер понадобится мастер-пароль либо заранее перенесённый ключ разблокировки. Старые `connections.json` и `credentials.vault` мигрируют в этот формат; не удаляйте исходники до проверки переноса.

Шестерёнка в боковой панели открывает отдельное окно с разделами «Общие» и «Тема». Доступны Tokyo Night, Catppuccin Mocha и сине-графитовая схема; Catppuccin Mocha на основе [официальной палитры](https://catppuccin.com/palette/) включена по умолчанию и оформляет весь интерфейс в одной системе. Сине-графитовая схема остаётся альтернативой. Системная/светлая и Noctalia темы в приложении не предлагаются. Выбор сохраняется в настройках приложения. Окно настроек можно закрыть крестиком или клавишей Escape и затем открыть снова.

Для переноса профилей используйте зашифрованный экспорт/импорт в настройках либо копирование `connections.dbdeck`. SQL-вкладка экспортирует только показанный результат (до 1000 строк); действие «Вся таблица в CSV» читает полный поток независимо от лимита предпросмотра. Импорт CSV открывает предварительный просмотр и сопоставление столбцов; SQL-файлы и PostgreSQL custom `.dump` восстанавливаются через меню подключения. Если у подключения несколько БД, перед операцией выбирается конкретная база.

## Файлы, экспорт и резервные копии БД

В настройках → «Общие» можно выбрать папку SQL-запросов и папку CSV. Без настроенной папки SQL команды «Открыть» и «Сохранить» всё равно открывают выбор файла. Все CSV-диалоги запоминают последнюю выбранную папку. Пути сохраняются в зашифрованном хранилище. Палитра команд, диалоги приложения и выбора файлов закрываются по Escape и клику в другую поверхность приложения; закрытие не подтверждает действие.

На карточке подключения доступны меню `⋮`, правая кнопка мыши и клавиша Menu. Действия: **структура БД без данных** и **полная резервная копия БД**. Для текущего подключения: `Ctrl+Alt+Shift+B` — структура, `Ctrl+Shift+B` — полный бэкап. На карточке: `Alt+B` / `Alt+Shift+B` — структура / полный бэкап. Нужны установленные клиентские утилиты совместимой версии: `pg_dump` для PostgreSQL, `mariadb-dump` или `mysqldump` для MySQL/MariaDB. PostgreSQL сохраняет структуру в SQL, полный бэкап — в custom-архив `.dump` для `pg_restore`; MySQL/MariaDB сохраняют SQL. Это копия выбранной базы, без глобальных ролей PostgreSQL.

Экспорт выполняется в фоне. Полный CSV читает один поток строк БД и пишет через буфер 1 МиБ, без накопления миллиона строк и повторных OFFSET-запросов. Прогресс виден в строке состояния; кнопка отмены и `Ctrl+Shift+X` останавливают экспорт/бэкап. Файл публикуется только после успешного завершения: ошибка или принятая отмена сохраняет прежний файл, временный удаляется. Файлы создаются с правами 0600. Пароль native backup передаётся через отдельный временный файл 0600, а не аргументы процесса. **Сами SQL/CSV/дампы не зашифрованы**: храните их в подходящем месте.

Для MySQL/MariaDB используется `--single-transaction --quick`: согласованный снимок обеспечивается для InnoDB, при отсутствии параллельных изменений структуры. Для нетранзакционных таблиц нужны отдельные меры согласованности. Восстановление доступно через меню карточки подключения и `Ctrl+Shift+I`; импорт CSV — `Ctrl+Alt+I`. Для CSV поддерживаются UTF-8, разделители запятая/точка с запятой/табуляция/вертикальная черта, заголовки и явное сопоставление полей. Запись идёт пакетами в одной транзакции; MySQL/MariaDB требуют InnoDB и строгого SQL-режима. Ограничение CSV: 1 МиБ на запись, 1024 поля; последовательности PostgreSQL после явного импорта identity автоматически не сбрасываются.

## Работа с production

При выборе PROD по умолчанию включается просмотр; выбранный режим TLS не меняется. Метка среды не ограничивает транспорт: доступны подключение без TLS, TLS без проверки сертификата и TLS с проверкой сертификата и имени. Обычный SELECT в PROD выполняется в READ ONLY транзакции даже при разрешённой записи. Каждая запись, сохранение правок, RW Commit или импорт требует ввода точного имени целевой БД. Подтверждение привязано к тексту запроса/снимку правок; изменение после открытия диалога требует нового подтверждения. Для намеренной записи через функцию в SELECT используйте «Выполнить с правом записи» (`Ctrl+Shift+Enter`). Ручную READ ONLY транзакцию нельзя повысить до RW: сначала завершите её.

При потере ответа на COMMIT результат может быть неопределённым: приложение закрывает сессию и не повторяет запись автоматически. Проверьте данные перед повтором. Используйте минимальные права, резервную копию с проверенным восстановлением и сначала тестовую копию для миграций. Тяжёлые SELECT/экспорты лучше выполнять на реплике и с подходящими фильтрами; лимит отображения не ограничивает работу запроса на сервере.

В настройках подключения можно указать **каталог утилит БД**. Для полного бэкапа и восстановления MySQL нужны штатные `mysqldump`/`mysql`, для MariaDB — `mariadb-dump`/`mariadb`. Приложение проверяет семейство клиента и отказывает при несовпадении. Для MySQL исправляется служебная обёртка CREATE TRIGGER из известной проблемы [MySQL #105990](https://bugs.mysql.com/bug.php?id=105990); тело определения сохраняется. Эта стадия потоковая, но требует второго временного файла размером с дамп. Неоднозначный/неподдерживаемый формат завершает экспорт ошибкой до замены файла. Утилиты должны быть совместимы с версией сервера; проверьте восстановление именно своей версии. PostgreSQL-восстановление сохраняет владельцев/ACL: соответствующие роли должны существовать на целевом сервере, глобальные роли в бэкап одной БД не входят. MySQL-бэкап DBDeck восстанавливается в БД с исходным именем, поскольку представления и процедуры могут ссылаться на него явно. Импорт выполняет доверенный SQL и команды нативного клиента; файл может обращаться к другим БД. Ошибка/отмена MySQL DDL может оставить частичный результат.

## Создать подключение и открыть таблицу

Если активного подключения нет, вместо пустого списка таблиц приложение показывает стартовый экран с кнопкой **Создать подключение**.

1. Нажмите **＋ Подключение**, выберите PostgreSQL или MySQL/MariaDB и заполните имя, адрес, порт, базу, пользователя и пароль. Перед созданием первого подключения DBDeck предложит создать мастер-пароль для локального зашифрованного хранилища.
2. Выберите метку окружения и цвет карточки. Флажок «Только просмотр» сохраняется в профиле и блокирует редактирование ячеек.
3. Нажмите **Проверить**, затем **Сохранить**. Пароль не записывается в JSON настроек.
4. Нажмите иконку подключения на карточке: каталог схем откроется сразу. После подключения рабочая область остаётся пустой до выбора объекта. Каждая схема показана отдельной раскрываемой строкой, а таблицы и представления находятся внутри неё; поиск фильтрует объекты по имени, в строке отображается только имя таблицы. Щелчок по карточке активного подключения возвращает к списку схем и таблиц, а зелёная галочка отключает его. Узкая иконная полоса слева переключает список подключений и объектов. У каждого соединения своя группа вкладок таблиц; при переключении соединения видны только его вкладки и последняя выбранная таблица. Обычный выбор объекта переиспользует активную вкладку; через контекстное меню правой кнопки можно открыть дополнительную. Полный путь находится в подсказке вкладки. Цвет профиля отмечает активное соединение и его вкладку.

Иконки навигации, добавления подключения, действий карточки и создания SQL-запроса центрируются внутри кнопок с небольшими отступами: иконки главной панели и добавления подключения — 28×28, действия карточки — 22×22, дерево схем и таблиц — 16×16. Между кнопками главной панели — 12 px, над рядом действий карточки — 6 px. Компактная круглая SQL-кнопка содержит значок 20×20. Вкладки данных и запросов имеют закруглённый верх, отдельные фоны активного/неактивного состояния и прозрачную область вокруг SQL-кнопки. В панели навигации состояния различаются яркостью: выбранный раздел — бирюзовый, доступные разделы — светло-серые, недоступные — серые. Остальные значки интерфейса берутся из системной темы **GNOME Adwaita**. В контекстном меню объекта доступны открытие в текущей/новой вкладке и экспорт показанных либо всех строк в CSV. Меню вызывается правой кнопкой по таблице в панели объектов.

Чтобы открыть SQL-редактор, нажмите значок запроса сразу после вкладок подключённой базы. При нехватке ширины вкладки прокручиваются, а кнопка остаётся видимой; её положение обновляется также при изменении ширины боковой панели. Каждая SQL-вкладка привязана к своей сессии БД. GtkSourceView подсвечивает SQL; completion предлагает ключевые слова, таблицы и поля из схем текущего подключения (`Ctrl+Space` открывает подсказки). Кнопка **Выполнить** или `Ctrl+Enter` запускает выделенный текст, а при отсутствии выделения — весь редактор. Поддерживаются SQL-операторы и скрипты с несколькими операторами; для скрипта показывается последний набор строк с данными. Параметры bind для raw SQL не поддерживаются, поэтому не вставляйте недоверенные пользовательские данные в запрос. Результат использует ту же сетку, что и просмотр таблиц. Интерфейс хранит до 1000 строк, 128 столбцов, 1024 символов в значении и 32 МиБ модели предпросмотра; CSV сохраняет показанный ограниченный результат.

Индикатор под редактором анализирует выделенный SQL, а без выделения — весь скрипт. Изменяющие команды (`INSERT`, `UPDATE`, `DELETE`, `DROP` и другие) вызывают предупреждение; слова внутри комментариев, строк, quoted identifiers и dollar-строк не учитываются. Неизвестный текст помечается «SQL не распознан», известные читающие команды — «Читающий запрос». Учитываются изменяющие CTE, несколько операторов и `EXPLAIN ANALYZE`. Это эвристика по SQL-тексту, без проверки синтаксиса и поведения пользовательских функций.

Режим «Только просмотр» запрещает запись из сетки, импорт и изменяющий SQL. Разрешён один распознанный читающий оператор: сервер проверяет его как одиночный запрос, выполнение проходит в READ ONLY транзакции. В Auto Commit транзакция чтения откатывается после результата. Это дополнительная защита: для production используйте отдельную учётную запись СУБД с правами только чтения и ограниченными правами вызова функций. READ ONLY не ограничивает нагрузку, внешние эффекты функций и административные возможности привилегированного пользователя.

Таблица использует виртуализованную отрисовку Tabulator: на экран попадают видимые строки, а при прокрутке DBDeck запрашивает следующую страницу по 200 строк. Запрос одной страницы не создаёт полный GTK-виджет на каждую ячейку. Кэш просмотра одной таблицы ограничен 10 000 строками и 32 МиБ модели; после достижения предела используйте фильтр или потоковый экспорт. Это лимит модели, а не всей памяти процесса GTK/WebKit. Максимум 64 столбца и 1024 символа на ячейку; длинные значения обрезаются на стороне БД, бинарные данные показываются в hex (до 511 исходных байт). Сортировка и фильтрация выполняются на сервере до постраничной выборки. Можно выделять диапазоны мышью и с Shift, копировать/вставлять диапазоны, редактировать ячейки двойным щелчком и растягивать столбцы; сохранение проходит через валидацию типов и ограничений БД. Изменения таблицы доступны только при загруженном первичном ключе. Результаты произвольного SQL ограничены первыми 1000 строками и 128 столбцами; выполнение SQL читает весь поток, чтобы сообщить точное число строк и завершить все операторы скрипта. Для тяжёлых запросов задавайте LIMIT и подходящие условия/индексы самостоятельно: предел клиентского предпросмотра не ограничивает работу сервера. Экспорт «Все строки» повторно читает полную таблицу потоком и не ограничен предпросмотром. SQL `NULL` записывается как `\\N`, текст `\\N` экранируется как `\\\\N`, пустая строка — как `""`. Текстовые поля CSV нейтрализуют формульные префиксы. Файл пишется атомарно и получает права только для текущего пользователя; при ошибке записи прежний файл остаётся целым. Каталог таблиц ограничен 1000 объектами. Без явной сортировки порядок строк не гарантируется. PostgreSQL использует указанную базу (по умолчанию `postgres`, если поле пустое); MySQL/MariaDB при пустой базе перечисляет доступные пользователю схемы. Цвет сейчас выбирается из семи встроенных оттенков.

Для удалённых подключений по умолчанию включена проверка TLS-сертификата и имени хоста. Можно выбрать TLS без проверки сертификата или отключить TLS для локальной/доверенной сети; не отключайте TLS для недоверенной сети.

## SQL-сессии, история и клавиатура

У каждой SQL-вкладки собственное соединение: TEMP-таблицы и параметры сессии не переходят в другую вкладку. В меню SQL (`Ctrl+.`) доступны ручные транзакции (`Ctrl+Alt+T`), Commit (`Ctrl+Alt+Enter`), Rollback (`Ctrl+Alt+R`), таймаут и сброс соединения с подтверждением (`Ctrl+Alt+Shift+R`). Остановить запрос — `Ctrl+Shift+.`. При незавершённом запросе или транзакции вкладку сначала нужно завершить; разрыв соединения не вызывает автоматического повтора запроса. MySQL DDL может делать неявный Commit, поэтому в ручном режиме такие команды запрещены.

История (`Ctrl+Alt+H`) и черновики хранятся внутри зашифрованного `connections.dbdeck`, входят в переносимую резервную копию. Черновики восстанавливаются только после явного подключения к той же БД; SQL автоматически не запускается. Учитываются ID профиля, СУБД, хост, порт, база, пользователь и TLS. После изменения адреса старые черновики доступны через историю для просмотра/копирования. Там же можно удалить выбранный черновик (`Ctrl+Shift+Backspace`). В истории: `Ctrl+L` — поиск, `Enter` / `Ctrl+Enter` — открыть без выполнения, `Ctrl+Shift+C` — копировать, `Escape` — закрыть. Лимиты: 100 выполнений, 32 сохранённые вкладки, 128 КиБ на SQL и 512 КиБ SQL на каждую коллекцию. Ошибка записи не закрывает SQL-вкладку.

Меню приложения — `Alt+M`, палитра команд — `Ctrl+Shift+P`, настройки — `Ctrl+,`, справка по сочетаниям — `Ctrl+Shift+?`. Основные команды не требуют F-ряда. `Ctrl+1` переводит фокус в SQL-редактор или таблицу, `Ctrl+2` — в результат SQL, `Ctrl+3` — в фильтры. Структура таблицы и DDL открываются через `Ctrl+Shift+D`; внутри инспектора `Ctrl+1…4` переключает разделы, `Ctrl+Shift+C` копирует DDL, `Ctrl+Enter` открывает его в редакторе без выполнения. DDL временных таблиц доступен только как диагностический текст.

При сохранении ячеек приложение сравнивает исходное значение с текущим в БД. Изменённое другим запросом значение или удалённая строка вызывают конфликт: пакет откатывается, локальные правки остаются для исправления. Проверка различает NULL, пустую строку, регистр и пробелы. Для MariaDB/MySQL пакетное сохранение поддерживает InnoDB; перед проверкой метаданных таблица защищается от конкурентного DDL до окончания транзакции. Бинарные, вычисляемые, обрезанные и непрочитанные значения этим способом не перезаписываются. Удаление строки — отдельная операция и не использует сравнение всех её исходных ячеек.

## Выделение, редактор и буфер

При открытии сетки выделения нет. До открытия редактора курсор над ячейками остаётся стрелкой, обычное выделение текста отключено; перетаскивание выделяет только диапазон. В редакторе текст светлый на тёмном фоне, разрешены каретка и выделение текста. Один клик выделяет ячейку спокойным фоном и внешней рамкой с маркером; двойной клик или Enter открывает встроенный редактор. Перетаскивание и Shift расширяют диапазон. Номера строк и заголовки выделяют строки/столбцы, включая протаскивание. Сортировка запускается только значком в заголовке. Стрелка показывает направление: вверх — по возрастанию, вниз — по убыванию; для таблиц состояние подтверждается после серверной загрузки. `Ctrl+A` выбирает все уже загруженные строки текущего представления, без запроса всей БД.

`Ctrl+C` и «Копировать» передают весь диапазон в системный GDK-буфер; пунктир обозначает скопированный диапазон. `Ctrl+V`/`Ctrl+Shift+V`, `Shift+Insert`, «Вставить» и контекстное меню заменяют выбранные значения. Копирование также доступно через `Ctrl+Insert`; Ctrl+C/V/A распознаются по физическим клавишам независимо от раскладки. TSV поддерживает CRLF, пустые поля, кавычки и переносы внутри кавычек. Вставка в одну ячейку расширяется по размеру источника до границы загруженных данных; вставка в диапазон повторяет источник по обеим осям и обрезает избыток. NULL копируется пустым текстом; для SQL NULL используйте Delete/Backspace или «Установить NULL». Первичные ключи, обрезанные/нечитаемые значения и read-only ячейки пропускаются. Escape отменяет открытый редактор; следующий Escape полностью снимает выделение и пунктир. После него работают обычный и Shift-клик.

Изменения таблиц остаются локальными до «Сохранить изменения»; «Отменить изменения» восстанавливает загруженные значения. Save/Discard явно завершают открытый редактор через Rust bridge. Пока идёт сохранение и обновление снимка, WebView блокируется. Догрузка следующей страницы сохраняет выделение и внесённые значения. Результаты SQL можно редактировать, когда запрос однозначно возвращает поля одной исходной таблицы вместе с полным первичным ключом. JOIN, агрегаты, вычисляемые поля и неоднозначные результаты остаются read-only. Правки SQL-результата сохраняются через ту же выделенную SQL-сессию; во время ручной транзакции редактирование результата отключено. Контекстное меню результата предлагает удаление строки; добавление и клонирование в нём отсутствуют.

JS/CSS компонента находятся в `assets/grid/`, локальный MIT Tabulator 6.6.1 — в `assets/vendor/`. Он включается в бинарник через `include_str!`: после изменений нужно закрыть старое приложение, пересобрать и запустить именно этот бинарник:

```sh
cargo build --locked --offline
./target/debug/zer0-dbdeck
```

## Проверки сетки

```sh
node tests/grid_logic.test.cjs
node --check assets/grid/grid.js
cargo fmt --check
cargo check --locked --offline
cargo test --locked --offline
```

Проверка настоящего компонента GTK/WebKit и Rust clipboard bridge (19 сценариев) запускается отдельно от остальных GTK-тестов. Она сохраняет WebKit-снимки выделения в `target/grid-*.png`:

```sh
cargo test --bin zer0-dbdeck --locked --offline webkit_grid_interactions -- --ignored --nocapture
```

GUI-тесты можно запускать без окон на рабочем столе: `tests/run-headless.sh` создаёт собственный виртуальный KWin, Wayland-сокет, D-Bus и временные XDG-каталоги. Нужны `kwin_wayland` и `dbus-run-session`. Системный дисплей пользователя не используется. Каждый GTK-сценарий запускайте отдельным процессом:

```sh
set -a
source .env
set +a
G_DEBUG=fatal-criticals tests/run-headless.sh cargo test --bin zer0-dbdeck --locked --offline application_staged_save_discard_and_paging -- --ignored --nocapture --test-threads=1
```

Другие сценарии: `sql_result_staging_and_delete`, `popup_dismissal_and_file_locations`, `sql_save_csv_and_backup_ui_handlers`. Они проверяют временные объекты отдельных соединений и не меняют постоянные таблицы фикстур. `million_row_csv_streams_and_cancel_preserves_file` проверяет потоковый экспорт миллиона синтетических строк и отмену; `native_schema_and_full_backups_postgres_mariadb_mysql` — шесть дампов существующих тестовых баз только чтением. Эти два теста дисплея не требуют. Полный цикл структура/бэкап → восстановление проверяет `tests/run-production-validation.sh` на отдельных одноразовых tmpfs-серверах PostgreSQL/MariaDB/MySQL. Он проверяет строки, FK, индексы, представления, триггеры, процедуры, PostgreSQL domain/identity/ACL, обрыв сессии и крупный CSV с отменой. `bash tests/run-tls-validation.sh` проверяет настоящий TLS/mTLS и отказ при неправильном CA/имени/отсутствии клиентского сертификата с готовыми публичными сертификатами rustls (путь `DBDECK_TLS_FIXTURES`, структура `certs/{ca,server,client}.crt` и `keys/{server,client}.key`). Тестовые сертификаты/ключи не создаются и не используются в приложении; тест меняет разрешение имени только в своём mount namespace. Оба runner требуют переменные из `.env`; существующие БД не удаляются.

## Тестовые базы данных

Docker Compose поднимает PostgreSQL, MariaDB и MySQL с общей таблицей `sample_records`, типизированной таблицей `typed_values` и разным числом специфичных таблиц, чтобы быстро отличать тестовые базы в интерфейсе. Порты опубликованы только на `127.0.0.1`.

```sh
cp .env.example .env
docker compose up -d
docker compose ps
./tests/apply-fixtures.sh
```

Фикстуры добавляют 16 разнотипных строк в `sample_records`, 8 записей в `typed_values` с датами, временем, десятичными числами, boolean, JSON, бинарными данными, NULL и длинным текстом, а также демонстрационные таблицы. Итого: PostgreSQL — 3 таблицы (`sample_records`, `typed_values`, `project_events`), MariaDB — 4 (добавлены `inventory_items`, `support_tickets`), MySQL — 5 (добавлены `audit_events`, `demo_orders`, `feature_flags`). Скрипт безопасно применяет их к уже созданным томам: создаёт отсутствующие таблицы и строки, не удаляя существующие данные. Повторный запуск допустим.

Параметры подключения:

| СУБД | Хост и порт | База | Пользователь | Пароль |
| --- | --- | --- | --- | --- |
| PostgreSQL | `127.0.0.1:55432` | `dbdeck_test` | `dbdeck_test` | `DBDECK_PG_PASSWORD` из `.env` |
| MariaDB | `127.0.0.1:53306` | `dbdeck_test` | `dbdeck_test` | `DBDECK_MARIADB_PASSWORD` из `.env` |
| MySQL | `127.0.0.1:53307` | `dbdeck_test` | `dbdeck_test` | `DBDECK_MYSQL_PASSWORD` из `.env` |

`docker compose stop` остановит контейнеры, сохранив их данные. SQL для начального наполнения лежит в `tests/fixtures/`; он выполняется при первом создании пустых томов. `.env.example` содержит только локальные тестовые пароли — не используйте их на реальных серверах.

Встроенного SSH-туннеля пока нет. Можно использовать отдельно настроенный защищённый туннель. Режим защиты соединения выбирается независимо от среды, включая PROD; отдельное разрешение для подключения без TLS не требуется. Закрытый клиентский ключ должен иметь права 0600/0400; при переносе профиля пути сертификатов нужно проверить заново.

Для интеграционной проверки после `docker compose up -d` экспортируйте пароли из `.env` и выполните `cargo test --test database_integration -- --ignored`. В zsh/bash:

```sh
set -a
source .env
set +a
cargo test --test database_integration -- --ignored
```

Тесты используют только локальные Compose-порты.
